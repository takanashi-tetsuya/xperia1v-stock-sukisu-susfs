Reviewed changes

- #3700: check_v2_signature permits exactly the v2 signing ID and APK verity
  padding, rejects every other ID, and still requires exactly one v2 pair.
  The existing bounded read_exact / nested-container parser is preserved.
- #3680: ksu_dup_sepolicy reserves 12 bytes per type for a self-type bitmap
  entry, derives the serialized length from policy_file's remaining capacity,
  passes that actual length to policydb_read, and stores it in the new policy.
- #3572: the target 5.15 filename-transition path checks datum, key and name
  allocations and the hashtab_insert result, freeing all newly owned objects
  on those failures. It does not free an existing table's objects on failure.
  The obsolete throne_tracker allocation path was not introduced.
- Non-SUSFS ksud escape now propagates the escape helper's error and uses
  current_cred rather than obtaining an extra credential reference. This is
  an inactive branch in the CONFIG_KSU_SUSFS=y delivery, not a claimed active
  device security defect.
- ksu_sulog_free_pending remains static with only its event.c call site and
  no declaration in event.h. This is linkage cleanup, not a security boundary.
- Makefile pins the verified official 40900 release number and explicit local
  full-version string. No git history count, network curl or fetch remains in
  version generation. Numeric 40900 does not imply all main-branch features.

Host verification

Run from the build directory:
  python3 tests/suki_security_test.py

The test extracts the actual production functions from the current files on
each run, builds two small C harnesses, and substitutes only dependencies.

42 APK cases passed:
- Unmodified official 40900 APK with SHA256
  4ca9810e6355fbff0bbe4bf5ce159808e64a40d85987a11894030cd990a6bdf3.
- Actual OpenSSL SHA256 certificate hashing against the production trusted
  key table, including rejection after certificate corruption.
- v2 only; verity padding before and after v2; EOCD comments.
- Unknown IDs before and after v2, including v3/v3.1 IDs and arbitrary IDs.
- Duplicate/missing v2, nested-length overflow, malformed pair/header/footer
  lengths, central-directory bounds, ZIP64 marker, truncation, short reads,
  empty/tiny inputs and file-open failure.
- Every opened test file was closed on success and error paths.

17 sepolicy cases passed:
- Allocation failure at each of datum/key/name, insert ENOMEM/EEXIST,
  successful insertion, duplicate update, existing matching output type,
  and missing source type.
- Serialization lengths of 100, 124 and 148 bytes with 148-byte reservation;
  correct rewind/read length, stored length and Android config bits.
- vmalloc/kmemdup failure, policydb_write/read failure, and insufficient
  serialization capacity, with balanced tracked allocation ownership.

Both harnesses passed AddressSanitizer and UndefinedBehaviorSanitizer with
-Wall -Wextra -Werror. LeakSanitizer is disabled because the command sandbox
uses ptrace; explicit allocation and open-file tracking checks cleanup.
Python bytecode compilation and the candidate git diff --check also passed.

Four temporary negative controls were rejected as expected:
- Removing the whitelist: the unknown-ID fixture was incorrectly accepted,
  and the test failed.
- Removing the first allocation check: UBSan caught the null datum access.
- Removing extra serialization capacity: the capacity/result check failed.
- Removing actual-length accounting: the mocked reader rejected the extra
  uninitialized-capacity bytes passed as serialized data.
These controls altered only temporary test harnesses, never production files.

Limits and deliberately preserved compatibility gap

The APK fixtures exercise the kernel's certificate identity parser. They do
not establish Android installation validity, full APK signature verification,
or exploitation on the Sony framework. Unknown-ID rejection is hardening;
the missing previous whitelist alone did not prove installed-app escalation.

The SELinux dependency mock honors policy_file remaining-length semantics and
policydb_read's own failure cleanup (confirmed in the local 5.15 source). It
does not establish that this Sony policy grows or replace a real policy parse,
serialize and load test. Non-SUSFS runtime behavior was source-reviewed only.

#3679 scoped su-session descriptors are intentionally NOT ported. The paired
official 40900 userspace and this kernel use UAPI 2; upstream scoped descriptor
handling requires coordinated kernel/userspace/UAPI changes. The residual gap
is restricted-profile/TTY compatibility, not proof that a generic descriptor
grants unrestricted commands. A mechanical ksu_install_fd rename would not be
a complete or compatible repair. This build must not be represented as having
the upstream scoped su-session behavior.

#3594 behavior is already superseded by the bounded #3613 parser; no duplicate
old hunk is required. This review does not extend coverage to kernels older
than the target 5.15 branch or validate an unpaired newer manager/userspace.
